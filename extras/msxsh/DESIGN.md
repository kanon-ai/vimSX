# 退避・復帰と RAM パイプ

## メモリ配置

|領域|用途|
|---|---|
|0100h～|シェル本体。コードは 6000h 未満|
|6000h～|シェルのデータ。ビルド時に B000h 未満を確認|
|C000h～C5FFh|常駐スーパーバイザ。DOS 呼び出し窓口、退避・復帰、パイプ|
|C600h～C77Fh|通信領域、BIOS ベクタ複製、子のコマンドテール|
|CBF0h から下向き|スーパーバイザ／マッパ転送用スタック|
|CFF0h から下向き|シェル用スタック|
|追加マッパ 3 セグメント|0000h～BFFFh の 48KB スナップショット|
|追加マッパ 1 セグメント|4KB × 2 の交互パイプバッファ|

シェル開始時に DOS2 の ALL_SEG でユーザーセグメントを 4 個確保します。途中で確保に失敗した場合も確保済み分を解放します。ページ 3 は切り替えません。マッパの取得／切り替えは DOS の API を使い、ポートを直接操作しません。

## 外部 COM の実行

1. 名前、拡張子、ファイルサイズ、テール長を検証します。
2. DOS2 FORK でプロセスを作り、継承可能に開いた標準入出力を渡します。シェルのスクリプトハンドルは継承しません。
3. 常駐コードへ移り、独立したスタックに切り替えます。下位 48KB を 3 セグメントへコピーします。
4. ページゼロの DOS 呼び出し先を C006h、BIOS ウォームブート先を C683h に設定します。DOS 呼び出し先は TPA 上端の役割も持ちます。
5. COM を 0100h に読み、コマンドテールと PARAMETERS / PROGRAM を渡します。子スタックは BFF0h、戻り先は 0000h です。
6. 子の TERM、RET または JP 0 で常駐コードへ戻ります。子のエラーハンドラを解除し、JOIN でハンドルとユーザーマッパセグメントを回収します。
7. 下位 48KB、元のページ構成、シェルスタックと IX/IY を戻します。子の終了コードを `$?` に反映します。
8. シェル終了時は親シェルで確保した 4 セグメントを解放し、DOS に終了コードを返します。

これはメモリ保護ではありません。子は同じアドレス空間で動きます。特権分離、任意プログラムのクラッシュからの回復、スロット変更や独自常駐処理の復元は保証しません。

## パイプ

常駐 DOS 窓口でハンドル 0 の READ と 1 の WRITE を処理します。RD_SEG / WR_SEG を使う間はページ 3 のスタックを使います。4KB 上限は加算の桁あふれを含めて書き込み前に確認します。EOF は DOS2 の C7h と 0 バイトを返します。

前段が終わるまで後段を起動しません。中間段では一方のバッファを読み、もう一方へ書き、次段で役割を交換します。ステージ数に比例したメモリ確保やディスクスプールは行いません。

## 制御構文と変数（0.2）

`control.h` は最大 4095 バイトのブロックを読み、96 ノードの固定配列へ構文を解析します。ノードは通常コマンド・if・for と、条件・本文・次ノードのインデックスを保持します。解析中にはコマンドを実行せず、fi / done まで揃って構文が正しい場合だけ評価します。ブロックの構文エラーや容量超過で、残りの本文を独立したコマンドとして誤実行しないよう、スクリプトを状態 2 で停止します。

通常コマンドの展開・リダイレクト・パイプ・COM ローダは既存の実行経路を使います。条件部と本文を実行する時点で変数を展開します。for のリストだけは開始時に一括展開し、深さごとの 512 バイト領域へ保存します。入れ子は最大 4 段で、break / continue は内側のループが処理します。スクリプト全体をメモリへ読み込む必要はありません。

シェル変数は 8 エントリの固定表で、各エントリが名前・値・export 属性を持ちます。参照はローカル表、次に DOS の環境の順です。通常の代入は表だけを更新し、export 属性がある場合は DOS の SENV も更新します。unset は双方から削除します。

構文ノード、ブロック本文、ループ進行状態、変数表はすべて下位 48KB に置き、従来のスナップショットで一緒に退避・復帰します。追加のマッパ確保はなく、4KB パイプと 4 セグメント予約の仕様は変わりません。
