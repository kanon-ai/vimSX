# MSXSH 0.2 スクリプト構文ガイド

MSX-DOS2 上で Linux ターミナルの気分を味わうための、独立した bash 風シェルです。GNU Bash の移植・完全互換ではありません。**実用性と安全性は未確定のジョーク／実験用ソフト**です。破棄してよいディスクのコピーやエミュレータで試してください。[免責](README.md#免責)と[検証範囲](VALIDATION.md)も参照してください。

## 1. スクリプトの起動

MSXSH.COM とテキストファイルのスクリプトを DOS2 ディスクに置き、DOS のプロンプトから実行します。

```text
A>MSXSH CONTROL.SH
```

[CONTROL.SH](examples/CONTROL.SH) は if / for / 変数のサンプル、[DEMO.SH](examples/DEMO.SH) は条件付き実行とパイプのサンプルです。どちらも [GREP.COM](https://github.com/kanon-ai/vimSX/blob/main/extras/search/GREP.COM) を同じディレクトリか PATH 上に置いてください。

`MSXSH` だけなら対話モード、`MSXSH -c "echo hello; pwd"` なら一行実行です。対話モードからスクリプトを起動する場合は、先に `exit` で DOS に戻ります。シェルの入れ子、`source` / `.`、BAT 実行、スクリプト引数、`$1` / `$@` は未対応です。

スクリプトは ASCII のテキストで作るのが確実です。CRLF と LF を受け付け、最後の行に改行がなくても実行します。UTF-8 BOM や NUL は付けないでください。1 行は 255 バイトまでです。`#` で始まる語以降は行末までコメントになります（引用符の中を除きます）。

```sh
# コメント
echo hello # ここもコメント
echo 'hello # world'
```

## 2. 変数・環境変数

```sh
DEMO_NAME=MSX
MESSAGE="Hello $DEMO_NAME"
echo "$MESSAGE"
echo "${DEMO_NAME}_DOS2"
export DEMO_NAME
DEMO_NAME=turboR
unset DEMO_NAME MESSAGE
```

|構文|動作|
|---|---|
|`NAME=value`|シェル内の変数を設定。`=` の前後に空白は入れない|
|`$NAME` / `${NAME}`|値を参照。未設定なら空文字列|
|`$?`|直前に実行したコマンド／制御構文の終了状態|
|`export NAME`|現在の値を DOS 環境へ渡し、外部 COM からも参照可能にする|
|`export NAME=value`|値の設定と export を同時に行う|
|`unset NAME`|シェル変数と DOS 環境の双方から削除|

通常の新規変数は外部 COM には渡りません。export 後の再代入は DOS 環境にも反映します。DOS から継承した非空の環境変数に代入した場合も環境へ反映します。シェル終了でローカル変数は消えますが、DOS 環境への変更は残ります。既存の PATH などを変える場合は元の設定に注意してください。

名前は英字・数字・`_` で、先頭に数字は使えません。シェルが保持する変数は 8 個、名前は 31 バイト、値は 255 バイトまで。ループ変数と export した変数もこの 8 個に含まれます。`unset` で空きを再利用できます。

`A=one B=two` の複数代入は可能ですが、同じコマンドの右辺は代入前にまとめて展開します。順番に新しい値を使うなら、`A=one; B="$A"` のように分けます。`NAME=value command` の一時的な環境指定、配列、`read`、算術展開、`${NAME:-default}` は未対応です。

## 3. 引用符と展開

```sh
X=hello
echo '$X'       # $X と表示
echo "$X MSX"   # hello MSX と表示
echo one\ two  # 空白を含む一つの引数
```

単引用符では変数を展開せず、二重引用符では展開します。引用符をまたぐ複数行文字列、コマンド置換 `$(...)` / バッククォート、算術展開 `$((...))` は未対応です。

展開した値を空白で再分割する機能はありません。`X="a b"; for i in $X; ...` の `$X` は、一つの値 `a b` として渡ります。ワイルドカードもシェルでは展開しません。`for f in *.TXT` は `*.TXT` という一つの文字列を扱います。LS / GREP / FIND に渡したワイルドカードは各コマンド側の仕様に従います。

バックスラッシュは空白・引用符・`$`・演算子などの前でエスケープに使えます。通常の文字の前では残るため、DOS の `A:\DIR\FILE.TXT` も扱えます。外部 COM へ渡す引数中のリテラル二重引用符は未対応です。

## 4. コマンドの接続と終了状態

```sh
echo first; echo second
true && echo success
false || echo failed
grep hello INPUT.TXT
echo "status=$?"
```

`;` と改行は順番に実行します。`&&` は直前が 0 のとき、`||` は 0 以外のときに後続を実行します。通常のコマンドが失敗しても、次の独立したコマンドは実行します。

一般に 0 は成功、0 以外は失敗です。GREP は一致なしで 1、シェルの構文・容量などのエラーは 2、不明なコマンドは 127、ロードできない実行形式などは 126 です。外部 COM 独自の終了コードも `$?` に渡ります。`exit` は直前の値、`exit 7` は指定した 0～255 の値で終了します。

## 5. if / elif / else

```sh
if [ -f INPUT.TXT ]; then
    echo "file exists"
elif [ -d INPUT.TXT ]; then
    echo "directory exists"
else
    echo "not found"
fi
```

条件部はコマンドです。終了状態 0 なら then 側、0 以外なら次の elif または else 側を実行します。else は省略できます。条件部に複数コマンドを書くと、最後の終了状態で判定します。

```sh
if echo "apple banana" | grep banana; then
    echo found
fi
```

`if true; then echo yes; fi` のような一行形式でも、`then` を次の行へ置く形式でも使えます。if の終了状態は実行した本文の最後の値です。どの分岐も実行しなければ 0 になります。

## 6. test / [ ... ]

`test` と `[ ... ]` は同じ判定を行います。`[` と `]`、演算子、引数の間に空白を入れます。論理式の結合は `&&` / `||` を使います。

|式|真になる条件|
|---|---|
|`[ "$A" = "$B" ]` / `==`|文字列が一致|
|`[ "$A" != "$B" ]`|文字列が不一致|
|`[ -n "$A" ]` / `[ -z "$A" ]`|文字列が非空／空|
|`[ -e FILE ]`|ファイルまたはディレクトリが存在|
|`[ -f FILE ]` / `[ -d DIR ]`|通常ファイル／ディレクトリが存在|
|`[ 1 -eq 1 ]` / `-ne`|整数が等しい／異なる|
|`-lt` / `-le` / `-gt` / `-ge`|整数の小なり／以下／大なり／以上|
|`[ ! -f FILE ]`|一つの判定を反転|

整数は -32768～32767。範囲外・不正な式は状態 2 です。`test` だけは偽、文字列一つだけなら非空が真です。`-a` / `-o`、正規表現、括弧による式のグループ化は未対応です。

## 7. for / break / continue

```sh
for item in apple banana "two words"; do
    if [ "$item" = banana ]; then
        continue
    fi
    echo "$item"
done
```

列挙した値を順に変数へ代入し、本文を繰り返します。値のリストはループの開始時に一度だけ展開します。`for item in; do true; done` の空リストは本文を実行せず、状態 0 になります。空文字列 `""` は一つの値です。

`break` は最も内側の for を抜け、`continue` はその for の次の値へ進みます。数値引数は使えません。ループ変数はループの後も最後の値を保持します。for の終了状態は最後に実行した本文の値です。

明示的な `in` と値の列挙が必要です。`for ((...))`、暗黙のスクリプト引数によるループ、`while` / `until` は未対応です。

## 8. ファイル入出力と小容量パイプ

```sh
grep hello <INPUT.TXT
echo first >OUTPUT.TXT
echo second >>OUTPUT.TXT
echo "apple banana" | grep banana | grep -n apple
```

`<` は入力、`>` は出力ファイルを作成／上書き、`>>` は追記です。**`>` は既存内容を失う操作**なので、サンプルの出力先にも重要なファイルを指定しないでください。`2>` / `2>&1` / ヒアドキュメントは未対応です。

パイプはマッパ RAM 上に置き、1 段の出力は最大 4096 バイトです。前段が終了してから後段を実行する逐次方式で、一時ファイルは作りません。上限を超える書き込みはエラーになり、残りの段を実行せず状態 2 になります。それまでのコマンドの副作用は取り消しません。

通常のパイプの終了状態は最後の段の値です。`pipefail` はありません。DOS2 の標準ハンドル 0 / 1 を READ / WRITE するプログラム向けで、BIOS 直接操作や任意の DOS アプリケーションには対応しません。[詳しい対応範囲](README.md#パイプの仕様)を確認してください。

明示した `<` / `>` はその段のパイプ指定より優先します。代入や `cd` / `export` / `unset` / `exit` / `break` / `continue` はパイプ中ではエラーです。

## 9. 対話入力・上限・未対応構文

対話モードで if / for を入力途中の場合は `> ` が表示され、続きを入力できます。Ctrl-C で入力中のブロックを捨て、状態 130 で通常のプロンプトへ戻ります。左右キー・Backspace・Delete、上下キーの行履歴（8 件）が使えます。複数行ブロックを一つの履歴として扱う機能はありません。

|対象|上限|
|---|---|
|物理行・一つの通常コマンド・for ヘッダ|各 255 バイト|
|制御ブロック|4095 バイト。改行・コメントも含む|
|if / for の入れ子|4 段。elif も 1 段として数える|
|内部の構文ノード|96 個|
|シェル変数|8 個、名前 31 バイト、値 255 バイト|
|for の展開済みリスト|区切り NUL を含め 512 バイト|
|通常コマンド|64 トークン、32 引数、展開領域 1024 バイト|
|外部 COM の引数テール|126 バイト|
|パイプ|1 段 4096 バイト|

if / for はブロック全体の構文を確認してから実行します。不完全なブロックやブロックの構文・容量エラーでは、状態 2 でスクリプトを停止します。残りの本文を単独コマンドとして実行しません。

制御ブロック全体をパイプ・リダイレクト・`&&` / `||` につなぐ構文は未対応です。例えば `for ...; done | grep ...` は使えません。これらの接続は条件部や本文中の通常コマンドへ指定してください。関数、case、サブシェル、ジョブ制御、バックグラウンド処理も未対応です。

詳細な動作条件は [README](README.md)、実際に確認した内容は [VALIDATION](VALIDATION.md)、退避・復帰の方式は [DESIGN](DESIGN.md) を参照してください。
