# カーソルと日本語の表示

各版の独自グラフィック表示では、NORMALのカーソルを文字セル全体の反転表示にします。
全角文字は2セル幅を使い、設定中の文字色と背景色を交換します。
INSERTとコマンド入力では左端の縦線を使用します。
移動・画面切り替え・終了時には、保存した画素を復元します。
通常版・従来描画版のKANJI表示は従来どおりDOS漢字ドライバが担当します。

## ASCII表示の日本語

`:ascii`、`:kanji`、40桁・80桁の手動切り替えは維持しています。
日本語を含むファイルを開いても、自動でKANJI表示へ変更しません。
ASCII表示は8ドット高のため、16ドットの日本語フォントを縮小し、
細い線や隙間が潰れる場合があります。日本語の字形を保つには
`:kanji` を使用してください。これは文書の文字コードを変換する操作ではありません。

旧版は最下段の半角幅だけを `XOR FFh` で反転していました。
青背景（4）・白文字（15）では水色（11）・黒（0）になるため、
カーソルの重なった「今」「。」などの下端が欠けて見えます。
本文の文字コードが壊れる問題とは異なります。

修正の検証途中で、ASCII表示中の全角文字に半角幅の反転カーソルを
描いてしまう条件漏れも確認しました。最終版ではASCII/KANJIのどちらでも
全角文字を2セル幅で扱います。これはエディタ側の問題です。

## 切り分けの対象

- GitHub公開ZIPの `v0.1.0-alpha.1` と修正版を区別して検証。
- エミュレータ：Hesoten/blueMSX-plus公式 `v3.2.0-alpha` x64配布物。
- RTL：hra1129/V9968_Cartridge、コミット
  `453d5f32b0cad874e7b9d4f885fae5f183afe024` の `fpga` 配下。
- 今回の比較にopenMSXは使用していません。テストディスクを構成する
  既存ユーティリティとしてのみ使用しています。

公式BlueMSX+から採取したVRAMと漢字ROMの字形を比較し、旧カーソル部分以外の
画素が一致すること、移動後に元の字形へ戻ることを確認しました。
SCREEN 7＋FILのアドレス式は、R#2全256値、Y全256値、両フィールド、
横256バイトの33,554,432通りでRTLとBlueMSX+が一致しました。
これはアドレス式の照合であり、全RTLのシミュレーションや形式的等価性証明ではありません。
全画面モード、全コマンド、Geo3D、サイクル精度、実機動作は今回の確認範囲外です。

内蔵V9968のBlueMSX+機種設定は `version=V9968`、`vram size=256kB` です。
これは基本バンクのサイズで、公式版のデバッグ表示では16バンク、合計4MiBを確認できます。
旧カスタム環境の `4096kB` 指定は公式版では起動時に受け付けられません。

修正はエディタのカーソル処理に限定しています。エミュレータやRTLを修正して
表示に合わせる変更は行っていません。
Undo/Redoの開発版はこの公開版には含めません。
