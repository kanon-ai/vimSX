# Undo / Redo

NORMALモードで `u` を押すと取り消し、`Ctrl+R` でやり直します。
`3u`、`3`の後に`Ctrl+R`を押す操作、`:undo`、`:redo`にも対応します。

- 挿入モード開始からEscまでの入力・改行・Backspaceをまとめて取り消します。
- `x`、`dd`、`p`、`P`、置換コマンドはそれぞれ1回の編集として扱います。回数指定も一まとまりです。
- 2ファイルの履歴は独立しています。`:bn`等で切り替えても保持します。
- 取り消し後に新しく編集すると、そのファイルのRedo履歴を破棄します。
- 保存した状態へUndo/Redoで戻ると変更印が消えます。保存位置の履歴が残っている場合に限ります。
- コピー領域はUndo/Redoで戻しません。履歴は保存ファイルに書かず、終了時に消えます。

## 履歴容量

文書全体のコピーではなく、変更したバイト・位置と編集単位の境界を記録します。
1バイトの挿入または削除を4バイトの記録にし、各編集単位に始点・終点の8バイトを使います。
日本語の全角文字は通常2バイト、置換は削除と挿入の両方として数えます。

|タイプ|1ファイル当たりの履歴領域|1回の編集で記録できる変更バイト数の上限|
|---|---:|---:|
|通常マッパ版|8KiB（空きセグメントが少ない場合4KiB）|2,045（4KiBの場合1,021）|
|V9968 VRAM版（4種）|256KiB|65,533|

複数の編集を記録する場合、その合計が領域内に収まる範囲で遡れます。
容量が足りなくなると古い編集単位から破棄します。
**1回の編集自体が容量を超えた場合は、そのファイルの履歴を消去し、
`Edit exceeds undo history` と表示します。その編集は取り消せません。**
編集内容はそのまま残り、次の編集から履歴記録を再開します。
編集の一部分だけを取り消して文書を壊すことはしません。
大きな貼り付け・削除・置換の前にはファイルのコピーを残してください。

通常版はDOS2から確保したマッパRAMの一部を履歴に使うため、空きRAMの構成により
文書・コピー領域が小さくなります。256KB以上という最低搭載RAM条件は変わりません。
V9968版は未使用VRAMを使い、1MiB×2文書と共通コピー領域を維持します。
物理VRAMの `340100–3800FF` を文書1、`380100–3C00FF` を文書2の履歴に使います。

Undo/Redoは障害復旧やバックアップの代わりにはなりません。
VimのUndoツリー、`U`による行単位復元、履歴の永続保存には対応していません。
