# 漢字モードの先頭文字欠けの修正（2026-11-23）

通常版VIMAPと互換描画版VIINT・VIEXTで、ASCIIからKANJIへ切り替えると
先頭文字の一部が欠ける不具合を修正しました。

ASCII用の左余白消去をDOS漢字ドライバの画面にも実行していたため、
漢字40桁では先頭文字の上半分、漢字80桁では先頭文字全体を消していました。
コロンがピリオドに見え、別モードへ戻すと復元される現象の原因です。
保存データはこの描画処理では変更されません。

修正は左余白消去を独自グラフィック描画時に限定する条件追加です。
V9968独自描画版VI9IN・VI9EXのCOMは変更していません。

## 検証

- 修正前3タイプ×40/80桁で、先頭のコロンが次行の同じコロンと異なることをVRAM比較で再現。
- 修正後の同じ6条件で、16行すべての画素が一致。保存内容も元データと一致。
- BlueMSX+通常版でモード往復、行番号、配色、入力・改行・保存・終了を確認。
- openMSX通常版で2ファイル間のコピー・削除・貼り付けと保存を確認。
- R800のASCII80入力は変更前約36.52ms/文字、修正後の漢字往復後約36.50ms/文字。
  この入力列では速度低下を再現していません。一般的な速度改善の主張ではありません。

結果は `validation-first-cell.json`、再現テストは `tests/kanji_first_cell.py` です。
速度はエミュレータ内経過時間で、ホスト実時間・実機速度の測定ではありません。
実機での検証は未実施です。
